# 旅游 AI 助手工程版设计规格

日期：2026-10-18
状态：用户已确认并授权实现；实际交付与验证范围见 ../../verification.md。

## 1. 目标与范围

交付可运行、可维护且便于学习的完整 pnpm workspace 工程。首个里程碑完成本地 Docker Compose 部署：React 前端、NestJS API、PostgreSQL 数据库与八个旅游工具形成完整闭环。第二个里程碑补齐云服务器部署配置与说明，复用相同应用镜像。

用户已确定：React、TypeScript、TailwindCSS、Ant Design；NestJS、TypeScript、DeepSeek、LangChain、LangGraph；PostgreSQL；SSE 流式输出；用户记忆；packages/shared 共享数据契约。

默认产品界面与文档使用中文。工程版面向个人用户，不加入支付、多租户管理后台或实际机票酒店交易。云端默认单台 Linux 云服务器，不在本地阶段实际创建云资源。

## 2. 架构选择

采用模块化单体与 pnpm monorepo。相比微服务，部署、调试与事务管理更简单；相比纯演示应用，提供认证、数据库迁移、工具输入校验、可观测错误及真实数据适配。

浏览器 → 同源反向代理 → NestJS → LangGraph → DeepSeek / 工具适配器；NestJS 同时访问 PostgreSQL。前端静态资源由 Nginx 提供，/api 路由到 API 服务。开发模式由 Vite 代理 /api。

目录约定：

- apps/web：页面、布局、聊天组件、工具表单、API 客户端、SSE 解析、认证状态。
- apps/api：auth、users、chat、agent、tools、memory、database、health 模块。
- packages/shared：Zod 输入输出 Schema、推导类型、工具目录、SSE 事件联合类型；不包含环境变量和密钥。
- database：数据库 Schema、版本化迁移及演示数据脚本。
- deploy/local：Docker Compose 与本地部署资源。
- deploy/cloud：云端 Compose、反向代理及环境变量说明。
- docs：知识体系、代码结构、开发流程、接口、安全边界、工具接入和部署排障。

依赖版本在实施时依据官方资料确认，使用 pnpm lockfile 固定。shared 必须先构建，web 与 api 共用相同 Schema，避免复制接口定义。

## 3. 用户流程与页面

用户注册或登录后进入主界面。侧栏展示会话列表与新建会话；主区域展示消息、流式回答和工具执行卡片；工具区提供八个工具入口，允许用户直接填写结构化表单。设置页展示个人偏好与长期记忆，支持修改和删除。

聊天发送支持停止生成、失败提示和重新发起请求。工具结果卡片显示数据来源、获取时间、数据模式和必要的不确定性说明。所有来自用户、模型和外部接口的文本按文本或禁用原始 HTML 的 Markdown 渲染。

## 4. 八个工具契约

所有工具具有固定 ID、中文名称、说明、Zod 输入 Schema 和标准结果封装。工具结果包含 status、data、sources、fetchedAt、mode（live/demo/estimated）以及可选 warning；错误包含稳定错误码、可读消息与是否可重试。

| 工具     | 核心输入                                 | 实现边界与输出                                                                                                   |
| -------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 行程规划 | 目的地、起止日期、人数、兴趣、节奏、预算 | 生成逐日活动、交通与费用建议；标注估算，校验日期和预算；不声称已预订                                             |
| 天气查询 | 城市或经纬度、日期                       | 地理编码与天气供应商适配；展示预报覆盖范围、时区和来源，超出覆盖范围明确返回不可用                               |
| 景点推荐 | 目的地、兴趣、数量                       | 通过景点数据供应商适配器获取候选，模型解释与排序；缺少供应商配置时只允许明确演示或模型建议，不伪造评分与营业时间 |
| 预算估算 | 天数、人数、币种、档次、交通住宿等项目   | 确定性计算项目明细、总额和预备金；单价为输入或明确标记的估算，计算不依赖模型心算                                 |
| 签证查询 | 国籍、目的地、旅行目的                   | 使用带来源与复核日期的受控规则数据；未知组合返回未覆盖及官方查询指引，模型不生成确定性入境结论                   |
| 货币换算 | 源币种、目标币种、金额                   | 通过汇率接口返回汇率、基准日期、换算额；失败明确报错，不用演示汇率冒充实时数据                                   |
| 打包清单 | 目的地、天数、天气、活动、同行情况       | 规则基础清单加模型个性化建议；按类别输出可勾选项目                                                               |
| 旅行翻译 | 原文、源语言、目标语言、场景             | DeepSeek 翻译与场景说明，限制输入长度；不伪称具备语音识别或语音合成                                              |

工具既可经认证后的结构化 HTTP 接口直接调用，也可由 Agent 自动选择。对外请求固定供应商域名，设置超时、请求大小与有限重试，避免把模型生成 URL 直接交给服务器抓取。

## 5. Agent 与 SSE

LangChain 封装 ChatDeepSeek 与结构化工具；LangGraph 以消息和执行上下文为状态，完成模型决策 → 工具执行 → 模型整理的循环。设置工具调用轮数与图递归上限，工具参数必须在执行前校验。用户身份由服务端注入，模型参数不得决定 userId。

聊天接口使用 POST /api/chat/stream，前端通过 fetch 读取 text/event-stream，支持认证头与 AbortController。共享事件协议包括 meta、token、tool_start、tool_result、error、done，各事件有 requestId 和单调递增序号。data 为单行 JSON，使用空行分帧；客户端处理跨 chunk 的 UTF-8、多行 data 和不完整帧。

meta 返回会话 ID；token 只携带最终用户回答增量，不暴露内部推理。tool_result 不回传凭据或完整内部异常。心跳保持连接，反向代理禁用响应缓冲并设置流式超时。客户端取消时传播 AbortSignal，停止模型和工具请求；服务端尽力落库已有部分内容并标记 interrupted。取消不是自动重试。

HTTP 响应开始前的错误使用标准状态码；开始后的错误使用 error 事件并结束流。每次请求最多一个 done。断线后通过会话消息查询恢复已保存内容，本期不实现事件游标续传。请求幂等键防止重试重复插入用户消息，已执行或进行中的请求返回清晰状态，不盲目重放有副作用操作。

## 6. 数据模型与记忆

PostgreSQL 使用版本化迁移。建议 Prisma 作为 ORM，最终版本兼容性在实施时验证。

- User：ID、唯一邮箱、密码哈希、创建时间。
- Conversation：ID、userId、标题、创建与更新时间。
- Message：ID、conversationId、role、content、status、requestId、创建时间。
- ToolExecution：ID、messageId 或 requestId、工具 ID、脱敏输入输出、状态、耗时。
- UserMemory：ID、userId、key、结构化值、来源、创建与更新时间。
- ChatRequest：ID、userId、conversationId、幂等键、状态和时间，用唯一约束控制重复请求。

会话短期记忆来自有界历史消息，超出预算时进行受控摘要。长期记忆仅保存偏好、预算档次、出行节奏等白名单字段，不自动存储护照、身份证、银行卡或其他敏感原文。第一版使用 PostgreSQL 结构化检索，不为满足名词增加向量数据库；语义检索作为后续扩展。

长期记忆默认经用户显式确认或在设置页填写后保存；从聊天中提取的候选偏好先提示确认。用户可查看、编辑和删除，删除后后续提示词不再读取。所有读写按认证用户过滤，跨用户资源按不存在处理。删除会话级联删除消息和执行记录，长期记忆独立管理。

## 7. 认证、配置与数据模式

邮箱密码认证，密码使用成熟哈希库。短期 Bearer token 保存在前端内存，刷新页面后重新登录，避免在 localStorage 长期保存令牌；本期不增加复杂刷新令牌体系。所有用户数据和工具接口默认认证。登录注册和模型接口限流；限制请求长度、并发与工具循环次数。

API 启动时校验环境变量。DeepSeek key 只存在服务端。提交 .env.example，真实 .env 忽略入库。生产模式必须设置独立数据库密码与强 JWT secret。

提供 live 与 demo 两种显式运行模式。demo 模式无需 DeepSeek 密钥，使用可预测的样例流和工具结果验证端到端链路，界面持续标识演示模式。live 模式缺少必须配置时启动失败或返回明确配置错误，绝不静默降级为演示。实时工具缺少数据或外部不可用时返回清晰状态。

## 8. 本地部署设计

本地 Compose 服务为 db、api、web。PostgreSQL 使用命名卷和健康检查；api 在数据库健康后执行迁移，再启动服务；web 通过同源代理访问 API。数据库默认不映射宿主机端口，需要调试时通过可选 override 配置开放。

使用多阶段 Dockerfile，分别构建 shared、api、web，生产镜像仅包含运行必需文件。容器使用非 root 用户运行可行的应用服务；API 提供存活与就绪检查，就绪检查覆盖数据库连接。Compose 配置重启策略、受控日志与持久化卷。

开发方式同时支持 pnpm dev（数据库由 Docker 提供）和 Docker Compose 全栈运行。README 提供 Windows PowerShell 与通用 shell 命令，首次运行步骤为复制环境变量、选择模式、构建启动、验证健康状态和打开页面。清理数据库卷必须单独明确说明，会销毁数据，不能作为常规启动命令。

## 9. 验证与本地验收

静态检查：所有 workspace 包类型检查、前端与后端构建成功，生产依赖完整。

单元与契约测试：共享 Schema 边界、预算计算、工具错误、SSE 跨 chunk 解析、Agent 工具次数上限及记忆白名单。

API 集成测试：注册登录、无认证拒绝、会话持久化、跨用户隔离、长期记忆 CRUD、幂等请求、流式协议和取消状态。

Docker 验收：Compose 配置可解析，镜像构建成功，数据库迁移成功，服务健康，前端可打开，demo 聊天及八个工具均可调用；重启容器后会话和记忆保留。live 集成依赖用户提供密钥和可访问的外部服务，缺少凭据时明确标记未验证，不能声称实测通过。

本地交付包含源码、锁文件、环境变量模板、测试、部署文件和中文文档。实际执行受当前机器 Docker 引擎、网络和凭据影响；报告逐项列出已执行结果及限制。
